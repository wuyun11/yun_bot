# 当前实现说明

本文档只描述 `yun_bot` 当前已经落地的功能和约定。

## 当前定位

当前项目是一个群聊 demo，采用：

- `nonebot-adapter-qq`
- 群共享聊天
- 最小 agent
- 群知识库检索

当前目标不是做完整平台，而是先把“群里能聊、能查、能录入一点知识”这条链跑顺。

## 当前能力

### 1. 对话能力

- `@机器人 ...` 会进入 agent
- agent 可以结合群共享历史决定是否调用 `rag_search`
- 群共享历史按群存储
- 每次问答后，都会把“用户消息 + 机器人回复”写入历史

### 2. 知识库能力

- `/rag 问题`
  - 直接检索当前群知识库
  - 不走 agent
- `/upload 文本`
  - 把一段字符串录入当前群知识库
  - 当前只支持文本录入，不做文件灌库

### 3. 用户名称能力

- 每个群维护一份用户名称映射 JSON
- 首次出现的用户会自动分配顺序名
  - `用户A`
  - `用户B`
  - `用户C`
- `/name`
  - 查看当前名称
- `/set name 新名称`
  - 设置当前名称

程序内部仍然使用 `user_id` 做映射和存储键，但传给 agent 的是映射后的用户名称，不再直接传 `user_id`。

### 4. 历史能力

- `/clear`
  - 清空当前群的共享聊天历史
- 聊天历史使用结构化 JSON 存储
- 历史文件只兼容当前新格式，不兼容旧格式

### 5. 帮助能力

- `/help`
  - 返回当前可用指令说明

## 当前指令

- `/help`
- `/name`
- `/set name 新名称`
- `/rag 问题`
- `/upload 文本`
- `/clear`

除此之外，`@机器人 直接说话` 会走 agent。

## 当前数据与目录

### 群历史

- 目录：`data/chat_history/`
- 维度：每群一份共享历史

### 用户名称映射

- 目录：`data/user_aliases/`
- 维度：每群一份映射文件

### 向量库

- 目录：`chroma_db/`
- 维度：按群隔离 collection

### 日志

- 目录：`logs/YYYYMMDD/`
- `main.log`
  - 当天公共日志
- `groups/<group_id>.log`
  - 当天每个群一份日志
  - 当前会记录 agent prompt、tool 调用、问答结果

## 当前行为边界

### agent 侧

- agent 不会自动持久化记忆
- 当前历史是项目代码手动存取的
- agent 每次运行时，都是重新读取群历史再执行

### RAG 侧

- RAG 仍然只是 chain，不是 agent
- `/rag` 只做纯检索问答
- 当前知识录入只支持字符串，不支持文件、引用消息、批量灌库

### demo 原则

- 当前项目是 demo
- 默认不兼容旧接口、旧数据格式、旧调用方式
- 新方案确定后，优先删除旧方案，而不是继续叠兼容层
